# 抖音私信 SDK 与宿主桥接

- 上游仓库：https://github.com/zhinjs/douyin-im
- 精确依赖：`douyin-im@1.1.0`，`v1.1.0` 对应提交 `f6eee669c39094224e00c6b877e1964d9da4e393`。
- 上游采用 MIT 许可证，原许可证与第三方声明随 `node_modules/douyin-im/` 进入发行资源；依赖版本和完整性记录在 `package-lock.json`。
- 本地 `bridge.mjs` 仅适配账号身份、扫码事件、收发、资料与历史，不复制或重写上游登录、签名及 Protobuf 协议。Python 适配器通过逐行 JSON 与其通信，每个业务账号独立进程、目录及停止生命周期。
- 为覆盖非好友客户的首次建聊和普通历史会话枚举，桥接使用固定版本现有的 `account.im.createPrivateConversation()`、`account.im.listThreads()` 和 `account.applyConversationInfo()` 等内部接口。它们不受上游公开类型兼容承诺保护，升级依赖必须重新检查并回归，不能仅修改版本号。
- 对已有身份绑定的账号，在该 SDK 实例的账号持久化入口先检查 UID，拒绝将误扫的其它账号提升为正式凭据；不修改依赖文件。宿主仍会在返回后核对绑定，防止同一业务账号的聊天记录混入另一身份。
- `1.1.0` 的 `beginLogin()` 会优先恢复正式会话，恢复错误会阻止生成二维码。显式扫码时仅临时将当前实例的入口导向原 `auth.beginLogin()`，结束后还原；外层仍调用原 `account.login()`，保留 generation、完成 Promise、取消清理及正式凭据提升逻辑。后台恢复不使用此入口，已有 UID 在宿主标记尚未生成时同样限制再次扫码的身份。升级必须复核这些内部生命周期接口。
- 固定实例的认证、设备、私信初始化及实时连接方法只增加阶段记录；RPC 和登录事件统一输出脱敏诊断。诊断只保留异常类型、白名单错误码、数字状态、静态接口路径及 SDK 源码位置，不转发原始异常文本、响应正文或带查询参数的地址。
- 不运行上游源码构建；按 npm 锁文件安装已发布产物，禁用安装脚本。运行时复用当前工程的 Playwright Node（要求至少 22.5），不依赖全局 Node 或 npm。
- SDK 原生账号文件包含登录凭据，宿主将新目录权限限制为当前用户和 SYSTEM；本地 DPAPI 标记只绑定业务账号与平台 UID。旧认证文件不迁移、不覆盖，也不作为新协议失败时的回退。
- 最终发送只有明确服务器成功回执才记为“已提交”；提交期间的网络、HTTP、解码失败或进程失联保持“结果待确认”，不自动重发。平台接受不表示对端收到或已读。
- SDK 原生心跳与重连由上游管理。有限重连补拉和显式历史查询都会经过宿主账号归属、去重、真实时间和历史副作用检查。
- 活动续期使用上游公开 `account.markActive()`：只转发收件箱内实际的前台输入，后端只查询已有账号进程；离线时不启动或恢复登录。10 秒合并、启动 `boot`、10 分钟活动窗口与空闲暂停由锁定 SDK 管理，宿主不使用定时器或被动收消息伪造活动。
- 上线后的 `token-beat` 安全验证仍交给原验证对象；验证链接只存内存，页面可继续或取消当前挑战，不要求重新扫码。链接在结束、取消和失败后清理；界面保留真实连接状态，是否续期成功仍由原 SDK 请求及平台响应决定。
- 离线 Node/Python 通信测试与构建检查不证明真实账号权限、平台投递或长时间在线稳定性；这些由用户使用自己的账号验收。
