# 引流工作台重构调研文档

## 当前状态

“引流工作台”上一版实现已经全部移除。当前只保留左侧栏入口：

- 定向引流
- 随机引流
- 任务与日志
- 数据表
- 引流设置

这些路由统一指向 `frontend/src/pages/TrafficPlaceholderPage.ts`，页面不渲染内容、不请求后端接口。后续重构应从本文档定义的数据结构、任务结构、自动化探测和 UI 规范重新实现，不复用上一版零散页面代码。

## 拓客工作台的页面规范

后续“引流工作台”必须与“拓客工作台”的信息密度和交互结构统一，不能做成新的视觉体系。

- 页面实现方式：继续使用 Vue render-function 写法，不引入新的 UI 框架。
- 共享组件：优先使用 `SplitPane`、`sectionTitle`、`emptyState`、`metricTile`、`iconBadge` 等现有工作台组件。
- 双栏结构：任务创建、设置、日志类页面采用可拖拽双栏，列表/队列在侧栏，详情/日志/配置在主栏。
- 表格结构：库切换、筛选、搜索、分页在表格卡片内完成；表格内部滚动，底部分页固定可见。
- 日志结构：任务详情先展示摘要和下一步建议，再展示固定高度日志窗口；日志窗口内部滚动，不撑高整个页面。
- 设置结构：主栏放授权、规则和执行参数，侧栏放环境状态、风险状态和危险操作。
- 顶部栏边界：“引流工作台”不能复用“拓客工作台”的顶部统计口径；引流需要自己的任务统计、限额和执行环境状态。
- 图标规范：页面标题只保留一个图标徽章，内部小节不要重复飞机图标。
- 内容原则：不要在定向/随机页面堆文案、图片、停留时间、每日上限等通用配置，这些应进入“引流设置”统一管理。

## 参考项目复盘

### GHkmmm/laizan

项目地址：[GHkmmm/laizan](https://github.com/GHkmmm/laizan)

完善度评价：最接近“引流工作台”的目标形态。它把 Electron、Vue3、Playwright、规则配置、任务历史、评论文案、图片评论、活跃度判断和随机停留串成了完整闭环，值得优先借鉴任务执行器和规则模型。

关键实现：

- 登录态：启动真实浏览器访问 `https://www.douyin.com/?recommend=1`，等待用户登录后读取 Playwright `storageState`，通过 `HasUserLogin=1` 判断是否登录。
- 执行入口：任务启动时使用已保存 `storageState` 打开推荐页，等待假视频图消失后进入循环。
- 视频元数据：监听 `aweme/v1/web/tab/feed/` 响应，把 `aweme_list` 缓存在 `Map<aweme_id, FeedItem>`，再通过 `[data-e2e="feed-active-video"]` 的 `data-e2e-vid` 反查当前视频。
- 跳过规则：没有视频信息、`aweme_type !== 0`、命中作者屏蔽词、命中视频简介屏蔽词、活跃度不足都会记录为跳过。
- 规则组：支持 v2 规则树，字段包括作者昵称、视频描述、视频标签；叶子节点绑定多文案和图片路径。
- 风控控制：评论前可随机观看 `watchTimeRangeSeconds`，浏览评论区 2-4 秒，评论逐字输入，每个字符 100-300ms，随机插入更长停顿。
- 活跃视频：打开评论区时监听 `aweme/v1/web/comment/list/`，根据评论响应做活跃度判断。
- 操作方式：点赞用快捷键 `z`，评论区开关用 `x`，下一个视频用 `ArrowDown`；切换前先确认评论区关闭。
- 数据记录：每个视频都记录作者、简介、标签、分享链接、停留时长、是否评论、跳过原因或评论内容。

可借鉴点：

- 用网络响应作为视频元数据来源，比只读 DOM 文本稳定。
- 动作前先判断页面状态，动作后记录成功/失败证据。
- 规则组与评论内容绑定，避免页面级任务表单堆满文案。
- 每个视频无论成功还是跳过都写入记录，便于后续数据表观察和防重复。

不能直接照搬点：

- 上一版 AI_Customer 的引流页已经被删除，不能只把 laizan 执行器塞进旧页面。
- laizan 的评论动作过重，AI_Customer 应先实现只读探测、登录态校验、切视频、点赞确认，再逐步开放评论和关注。

### paopaojun/Douyin_Curation_Assistant

项目地址：[paopaojun/Douyin_Curation_Assistant](https://github.com/paopaojun/Douyin_Curation_Assistant)

完善度评价：动作体系不如 laizan 聚焦引流，但它在“浏览器会话健康、动作确认、失败截图、实验室抓包、任务/规则/日志模型”上更像工程化系统，适合借鉴后端任务和日志设计。

关键实现：

- 会话矩阵：同时评估环境 Cookie、运行时缓存、持久化浏览器 Profile，按 `loginReady`、`hasSessionCookie`、`verificationRequired`、`loginPromptVisible` 打分选择可用会话。
- Profile 修复：可把可用 Cookie 写入 runtime/lab 浏览器 Profile，但不会绕过登录或验证码。
- 页面安全检查：动作前检查是否进入 captcha/verify 页面、是否出现登录提示、是否存在登录遮罩。
- 动作确认：点赞/收藏前读状态，若已点赞直接返回；点击后再次读取状态，未确认成功就报 `DOUYIN_ACTION_NOT_CONFIRMED`。
- 失败证据：动作失败时保存截图到 `.runtime/action-failures`，必要时保持浏览器窗口打开供人工排查。
- 评论输入：先打开评论区，再用多组 selector 找 textarea/input/contenteditable，填入内容后尝试点击“发送/发布/评论”，失败再回车。
- 推荐流翻页：优先在 `[data-e2e="slideList"]` 上 hover 后滚轮，再尝试大滚轮、PageDown、ArrowDown；每次都比对 `feed-active-video` 的 `data-e2e-vid` 是否变化。
- 实验室：提供独立 lab Profile，记录请求、响应、失败请求、console、页面错误、弹窗、跳转、会话健康和人工动作标记；用 `Ctrl+Shift+1/2/3` 标记手工点赞/收藏/评论，以便回溯真实请求。
- 数据模型：`ActionRule` 定义规则条件、动作和评论策略；`ActionTask` 定义任务的审核状态、执行状态、草稿文案、匹配快照；`ActionExecutionLog` 记录 taskId、workId、actionType、level、phase、message、details。

可借鉴点：

- 引流工作台必须有会话健康检查，不应该直接点按钮就假定抖音已登录。
- 每个动作都要有“前状态 -> 动作 -> 后状态确认”，不能只看点击是否执行。
- 浏览器实验室应先用于确定真实页面结构和请求，再进入批量执行。
- 任务与日志页面应以任务、规则、执行日志为后端事实，而不是前端临时状态。

不能直接照搬点：

- DCA 里存在浏览器上下文直接调用抖音接口的实验路径。AI_Customer 首版不建议走直接接口写入，先采用浏览器真实交互和页面状态确认，减少签名和风控不确定性。

## 重构建议架构

### 数据层

建议先建立以下概念，不急着堆前端表单：

- `traffic_rules`：规则组。保存名称、启用状态、优先级、来源模式、视频/作者/评论过滤条件、动作开关、限额策略、文案策略、图片策略。
- `traffic_campaigns`：计划。用户创建的定向或随机引流计划，引用规则组和执行参数。
- `traffic_runs`：批次。一次启动生成一个批次，记录开始/结束时间、状态、停止原因、统计摘要。
- `traffic_run_items`：视频队列项。记录视频 ID、来源、作者、简介、点赞数、评论数、是否直播/广告/未知、匹配规则、处理状态。
- `traffic_action_logs`：动作日志。按阶段记录 `probe/open/advance/like/follow/comment/skip/error`。
- `traffic_comment_records`：已评论/已处理视频记录。字段至少包括视频简介、评论内容、作者、视频点赞数、评论数、视频链接、视频 ID、动作时间、任务批次、跳过原因、截图路径。
- `traffic_dedup_ledger`：防重复账本。以平台、视频 ID、作者 ID、评论内容 hash、动作类型组成唯一键，控制同视频/同作者/同内容重复触达。

### 任务生命周期

任务不应等同于“前端点一次按钮”。推荐拆分：

1. 计划：长期保存的配置，例如“关键词 A 定向评论”。
2. 批次：用户每次启动计划时生成，负责本次运行状态、限额和统计。
3. 队列项：本批次将处理的视频列表或推荐流现场发现的视频。
4. 动作：对单个视频执行点赞/关注/评论中的一个或多个动作。
5. 日志：每个动作和状态变更都写入日志。

任务状态建议：

- `draft`：计划草稿，未启动。
- `queued`：批次已创建，等待执行。
- `running`：执行中。
- `pausing`：收到暂停请求，当前视频处理完后停止。
- `stopped`：人工停止。
- `completed`：达到上限或队列耗尽。
- `failed`：登录、验证码、页面结构、浏览器或动作确认失败。

停止规则建议：

- 出现登录弹窗：立即停止，提示重新登录。
- 出现安全验证/人机验证：立即停止，不尝试绕过。
- 连续 N 次没有活跃视频节点：停止，判定页面不在可执行流。
- 连续 N 次翻页后视频 ID 不变：停止，判定翻页失效。
- 连续 N 次动作未确认：停止，防止无效点击。
- 达到每轮/每日上限：完成，不继续刷。

### 规则和限额

引流设置页应统一管理：

- 多文案：按启用状态随机抽取；可记录使用次数和最近使用时间。
- 图片：可选单图或图库随机；图片上传失败时应停止当前动作，不应只发空文案。
- 动作开关：点赞、关注、评论、图片评论分别控制。
- 每轮上限：单次批次最多处理多少视频、最多评论多少条、最多关注多少人。
- 每日上限：按设备/账号/业务分别统计。
- 停留秒数：最小/最大观看时间，执行时随机取值。
- 视频过滤：直播、广告、未知视频、无评论入口、无关注入口的处理策略。
- 活跃度过滤：最低点赞数、最低评论数、最近评论时间、评论区可解析性。
- 风控暂停：登录、验证码、页面空转、动作确认失败、连续跳过过多时自动停机。

定向引流页面只负责选择来源和创建计划：

- 已采集关键词引流：从后端拉取拓客工作台已采集关键词，点击填入。
- 搜索关键词引流：用户手动输入关键词，由执行器打开抖音搜索结果并处理。
- 竞品视频引流：从拓客工作台已入库竞品账号/内容中选择视频队列。

随机引流页面只负责启动随机推荐流计划：

- 打开抖音推荐流。
- 随机进入一个视频。
- 对后续刷到的视频按统一规则执行。

### 防重复机制

防重复必须落库，而不是只靠 DOM 标记或内存 Set。

- 视频级唯一键：`platform + video_id + action_type`。
- 作者级冷却：同一作者 N 小时/天内最多触达一次。
- 内容 hash：同一文案对同一作者/视频不重复发送。
- 批次内去重：运行时内存 Set 提前挡掉重复队列项。
- 历史去重：启动任务前查 `traffic_dedup_ledger`。
- 成功动作和明确跳过都可写入账本，但要区分 `commented/skipped/failed`，失败不一定占用长期去重。

### 自动化执行器

推荐分三层：

1. `probe`：只读探测。检查登录、验证码、当前页面类型、活跃视频、可用按钮、视频 ID、作者、简介、点赞数。
2. `navigator`：导航层。负责打开推荐页、搜索页、详情页、切到下一个视频，并确认视频 ID 变化。
3. `actor`：动作层。负责点赞、关注、打开评论区、输入评论、上传图片、发送评论，并做前后状态确认。

执行器不要一上来就评论。推荐实现顺序：

1. 只读探测脚本。
2. 推荐流打开和随机进入视频。
3. 下滑/翻页并确认视频 ID 变化。
4. 点赞动作确认。
5. 关注动作确认。
6. 打开评论区并只读解析评论。
7. 文案评论。
8. 图片评论。

## 本次安全探测脚本

新增脚本：[script/douyin_probe.cjs](../script/douyin_probe.cjs)

脚本能力：

- 打开 `https://www.douyin.com/?recommend=1` 或指定 URL。
- 使用专用浏览器 Profile：`runtime/douyin_probe_profile`。
- 可连接已有 CDP：`--cdp http://127.0.0.1:9222`。
- 采集登录弹窗、安全验证、活跃视频、slideList、点赞按钮、收藏按钮、评论按钮、评论侧栏、关注按钮、直播/广告疑似信号。
- 可选 `--advance` 只测试翻页，不做点赞、关注、评论。
- 输出 JSON：`runtime/douyin_probe/latest.json`。
- 输出截图：`runtime/douyin_probe/latest.png`。

运行命令：

```powershell
# 临时安装 Playwright，只用于本次探测，不写入项目 package.json
$probeDeps = Join-Path $env:TEMP 'ai_customer_probe_deps'
npm install playwright --prefix $probeDeps --no-save

# 指向临时依赖目录，让 Node 可以加载 playwright 包
$env:NODE_PATH = Join-Path $probeDeps 'node_modules'

# 打开抖音并做只读探测，--advance 只测试切换视频，不触发点赞/关注/评论
node script\douyin_probe.cjs --advance --wait-ms 5000
```

本次探测结果：

- 脚本成功通过 Chrome 持久化 Profile 打开抖音：`launchMode = persistent:chrome`。
- 页面落点是 `https://www.douyin.com/jingxuan`，不是推荐流 feed。
- 没有发现 `[data-e2e="feed-active-video"]`，没有发现 `[data-e2e="slideList"]`。
- 安全翻页未生效：`navigation.advanced = false`，原因是没有活跃视频 ID 可比对。
- 首次截图出现登录弹窗，说明专用 Profile 没有可复用登录态；后续即使未弹出完整登录框，也仍未进入可执行推荐流。
- 没有执行点赞、关注、评论或图片上传。

结论：

- 后续真实执行器必须先做页面类型校验，确认处于推荐流/详情页且存在活跃视频 ID，才能进入动作层。
- 如果停在 `douyin.com/jingxuan` 或登录页，任务应失败并提示登录，不应继续点击。
- 下一次验证应先用 `--keep-open` 打开专用 Profile，由人工扫码登录，再复用同一 Profile 运行 `--advance`。

5. 实现“数据表”：已评论/已处理视频表，支持按批次、作者、动作、时间筛选。
6. 接入 `probe` 和 `navigator`，先让随机引流能稳定打开推荐流、进入视频、下滑并确认 ID 变化。
7. 只开放点赞动作并做前后状态确认。
8. 再开放关注、评论、图片评论。
9. 定向引流最后接入拓客工作台关键词/竞品视频队列。

## 风险边界

- 不实现验证码、人机验证绕过。
- 不实现代理绕过平台跨域或签名校验。
- 不在未确认登录态时执行动作。
- 不在无法确认视频 ID 的页面执行动作。
- 不把“点击成功”当作“动作成功”，必须读后状态或网络响应。
- 不做无限循环，所有任务必须有每轮/每日上限和连续失败停机条件。
- 不把文案、图片、限额散落在定向/随机页面，统一进入设置页。
